01 / กลไก

เปลี่ยนเส้นทางวิเคราะห์ ไม่ใช่แค่เปลี่ยนชื่อตัวแปร

กลไกแต่ละชั้นมีเป้าหมายเพิ่มจำนวนหลักฐานและงบประมาณที่ analyzer ต้องใช้ โดยขึ้นกับรูปแบบ artifact และเครื่องมือวิเคราะห์

01 — DECOYS

หลักฐานลวงที่สอดคล้องกัน

เพิ่ม metadata, diagnostics, control flow และ semantic paths ที่นำการอนุมานออกจากตรรกะจริง

02 — EXHAUSTION

ภาระด้านทรัพยากรและความหมาย

ขยาย headers, nesting, interfaces และ call graphs เพื่อเพิ่มงานหรือเข้าถึงขีดจำกัดของ analyzer

03 — TOKEN COST

โทเคนที่ต้องอ่านมากขึ้น

เพิ่มหลักฐานที่โมเดลต้องพิจารณา ทำให้การสรุปและ reconstruction ใช้ขั้นตอนกับโทเคนเพิ่มขึ้น

02 / เวิร์กโฟลว์

จาก exposure สู่หลักฐานที่ตรวจทานได้

ทำงานบนสำเนาใน staging เก็บต้นฉบับ และใช้รายงาน HTML แบบ standalone ที่เปิดออฟไลน์ได้ประกอบการตัดสินใจ release

01

AUDIT

ตรวจ exposure และจุดเสี่ยง แล้วบันทึกด้วย axobfus audit ./dist --report ./reports/audit.html

02

DEFEND

ใช้ pipeline ป้องกันและเก็บผลด้วย axobfus defend ./dist --report ./reports/defend.html

03

VERIFY

เปรียบเทียบกับต้นฉบับด้วย axobfus verify ./dist.protected ./dist แล้วรัน test suite ของผลิตภัณฑ์

03 / Artifact

การป้องกันที่เข้ากับรูปแบบไฟล์

AxObfus เลือกกลไกตามชนิด artifact แทนการใช้วิธีเดียวกับทุกไฟล์

JavaScript / Electron

Semantic decoys, IPC protection, source-map controls และ analyzer workload

WebAssembly / Python

Custom sections, interface expansion, marshal metadata และ decoy paths

Native binaries

ELF, Mach-O และ PE metadata รวมถึง compile-time header integration

Data / Models / Mobile

SQLite, Safetensors, GGUF, DEX และ IL2CPP structures ตามความเหมาะสม

เพิ่มต้นทุน ไม่ใช่คำมั่นถึงความลับสมบูรณ์

ไม่มี client-side protection ใดรับประกันการป้องกันนักวิเคราะห์ที่มีเวลา เครื่องมือ และสิทธิ์ runtime ไม่จำกัด เก็บ private keys และ master secrets ไว้ฝั่งเซิร์ฟเวอร์ ใช้ AxObfus เป็นส่วนหนึ่งของ defense-in-depth และประเมินผลกับ artifact ของคุณเอง
