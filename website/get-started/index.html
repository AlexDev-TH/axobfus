Get started / ใช้งานจริงใน staging

ตั้งค่า. ป้องกัน.
เก็บหลักฐาน.

เริ่มจาก artifact สำเนาที่คุณเป็นเจ้าของ ใช้ Node.js ^22.23.4 || >=24.0.0 และแยกไฟล์ต้นฉบับไว้สำหรับ verification

ใช้จากซอร์สด้วย npm ci && npm run build แล้วเรียก node dist/cli.js ส่วนคำสั่ง npx axobfus ใช้ได้เมื่อแพ็กเกจเผยแพร่บน npm แล้ว

  1. 01

    ลงทะเบียนกับ coding agent

    ตั้งค่า MCP server axobfus และทักษะ Counter-REA ให้ client ที่รองรับ หรือข้ามขั้นตอนนี้หากใช้ CLI อย่างเดียว

    npx axobfus setup
npx axobfus doctor
  2. 02

    ตรวจ exposure ก่อนแก้ไข

    รัน audit บน build output และเขียนรายงาน HTML เพื่อ review จุดที่ analyzer อาจใช้เป็นหลักฐาน

    axobfus audit ./dist --report ./reports/audit.html
  3. 03

    ป้องกันโครงการหรือ target ที่ระบุ

    ใช้ harden เพื่อค้นหา build output อัตโนมัติ หรือใช้ defend เมื่อต้องการระบุ target และเก็บรายงาน pipeline

    npx axobfus harden .

axobfus defend ./dist --report ./reports/defend.html
  4. 04

    ตรวจสอบเทียบต้นฉบับ

    ระบุ path ของ artifact ที่ป้องกันแล้วและต้นฉบับตาม output จริง จากนั้นรันชุดทดสอบของผลิตภัณฑ์

    axobfus verify ./dist.protected ./dist

Report / HTML

อ่านผลร่วมกับบริบท

--report ใช้กับ audit และ defend เพื่อเก็บข้อมูล exposure, กลไกที่ใช้ และค่าประมาณ token consumption รายงานช่วยการตรวจทาน แต่ไม่ใช่ใบรับรองความปลอดภัยหรือผล benchmark สากล

  • กำหนดสิทธิ์ไฟล์รายงานให้เหมาะสม
  • ตรวจข้อมูล sensitive ก่อนเผยแพร่
  • เปรียบเทียบผลจาก target และ environment เดียวกัน
axobfus audit ./dist/app.js \
  --report ./reports/app-audit.html

axobfus defend ./dist/app.js \
  --report ./reports/app-defend.html

ก่อน merge หรือ release

การป้องกันไม่แทนการทดสอบซอฟต์แวร์ ตรวจ functional behavior, packaging, signing, compatibility และ performance ตาม workload จริง

  • สำรองต้นฉบับและทำใน staging
  • รัน verify และ test suite ของโครงการ
  • เก็บรายงานเป็นหลักฐาน ไม่ใช่คำรับประกัน

สำหรับผู้ดูแล source

ใช้คำสั่งเหล่านี้เพื่อตรวจสอบ repository ใน environment ของคุณ การแสดงคำสั่งไม่ได้หมายความว่าทดสอบถูกรันหรือผ่านแล้ว

npm run build
npm test
