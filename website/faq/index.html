FAQ / ข้อเท็จจริงก่อนใช้งาน

คำถามที่ควรถาม
ก่อนป้องกัน build.

คำตอบสั้นสำหรับการติดตั้ง การอ่านรายงาน และขอบเขตที่ AxObfus ไม่อ้างเกินจริง

AxObfus คืออะไรและเหมาะกับใคร

AxObfus โดย AlexDev เป็น CLI และ MCP server สำหรับเจ้าของซอฟต์แวร์และนักวิจัยที่ต้องการลด exposure ของ artifact ต่อ Reverse-Engineering Agents โดยใช้ decoys, resource/semantic exhaustion และการเพิ่ม analyzer token consumption

ต้องติดตั้งอย่างไร

ใช้ Node.js ^22.23.4 || >=24.0.0 แล้วเรียกผ่าน npx ได้โดยไม่ติดตั้ง global

npx axobfus setup
npx axobfus harden .

หรือติดตั้งแพ็กเกจ axobfus ในโครงการแล้วเรียก axobfus --help

harden, defend และ protect ต่างกันอย่างไร

harden ค้นหา build output ในโครงการและทำ workflow อัตโนมัติ defend รัน pipeline กับ target ที่ระบุ ส่วน protect ใช้เมื่อต้องการควบคุมเฉพาะขั้นตอน shield และ output ดูตัวเลือกจริงด้วย axobfus <command> --help

บันทึกรายงานอย่างไร

ใช้ --report กับ audit และ defend

axobfus audit ./dist --report ./reports/audit.html
axobfus defend ./dist --report ./reports/defend.html

ไฟล์ HTML แบบ standalone เปิดออฟไลน์ได้โดยไม่มีสคริปต์หรือทรัพยากรภายนอก ใช้ review หรือเก็บเป็น CI artifact ได้ แต่ต้องตรวจข้อมูลที่อาจ sensitive ก่อนแชร์

ตัวเลขโทเคนในรายงานเป็นผลทดลองจริงหรือไม่

ต้องอ่านชนิดของค่าในรายงาน ค่าประมาณ token/cost เป็นแบบจำลอง ไม่ใช่ผลวัดกับ analyzer ทุกตัว หากต้องการอ้างผลเชิงประจักษ์ ให้รัน analyzer ใน environment ที่ควบคุมได้และบันทึกเวอร์ชัน การตั้งค่า และผลดิบแยกต่างหาก

AxObfus รับประกันว่า runtime จะเหมือนเดิมหรือไม่

ไม่ควรถือเป็นคำรับประกันโดยไม่ทดสอบ ใช้ axobfus verify <protected> <original> แล้วรัน test suite, format validation, packaging และ workload จริงของผลิตภัณฑ์เสมอ

ป้องกัน reverse engineering ได้สมบูรณ์หรือไม่

ไม่ได้ AxObfus เพิ่มต้นทุนและความกำกวมให้การวิเคราะห์อัตโนมัติ แต่นักวิเคราะห์ที่มีเวลา เครื่องมือ และ runtime access อาจยัง reconstruct ได้ เก็บ private keys และ master secrets ไว้ฝั่งเซิร์ฟเวอร์ พร้อมใช้ defense-in-depth

ใช้กับซอฟต์แวร์ของผู้อื่นได้หรือไม่

ใช้เฉพาะ artifact ที่คุณเป็นเจ้าของหรือได้รับอนุญาตชัดแจ้งให้แก้ไขและเผยแพร่ อ่าน Disclaimer ก่อนใช้งาน
